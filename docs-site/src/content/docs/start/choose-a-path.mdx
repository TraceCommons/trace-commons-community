All four paths produce the same core contribution envelope and enforce local redaction. The difference is who discovers the source trace and how much control you want to automate.

| If you want to… | Use | Best first step |
| --- | --- | --- |
| Select existing Claude Code or Codex sessions from a terminal | **Contributor CLI** | [Build and log in](/cli/quickstart/) |
| Review submissions visually and manage project-level behavior | **Desktop app** | [Understand the GUI model](/gui/overview/) |
| Contribute work produced inside Ironclaw | **Ironclaw integration** | [Enroll Ironclaw](/ironclaw/quickstart/) |
| Submit traces from another agent, harness, or product | **Direct API** | [Follow the API flow](/api/quickstart/) |

## A quick decision

1. If the session already exists in Claude Code or Codex, begin with the contributor CLI.
2. If you prefer a review queue and project controls, use a desktop app backed by the contributor daemon.
3. If Ironclaw produced the work, use Ironclaw's native integration so capture, redaction, queueing, and attribution share the same user scope.
4. If none of those own your trace format, build an adapter that emits the protocol envelope and submits it through the API.

:::note[Do not upload a raw transcript]
The ingest endpoint accepts a Trace Commons contribution envelope, not an arbitrary conversation export. Start with the [envelope contract](/api/envelope/) when implementing a new source adapter.
:::
